## 1. Summary of implementation

Two pages from `feat-openlings` are added to current upstream OpenBot as lazy routes. They sit outside the API-key, backend and setup gates, because they only need static files:

- **`/lab/openlings`**, the Openlings Character Lab: the rigged Openling with six clips, five expressions plus blink, 13 props, six role presets, a props gallery and several Openlings at once. The static lookdev GLB is kept as the visual baseline.
- **`/lab/office`**, the Living Office: eight zones, eight Openlings running the scripted simulation, camera presets, focus and follow, greeting, the chat panel with simulated task assignment and queues, day/evening lighting, quality levels, and the responsive and phone layout.

Both pages are local and simulated. They make no backend or LLM calls and persist nothing. three.js loads only in the lazy chunks, never in the main bundle.

**How it was built**
- 37 of the 58 files are copied byte-for-byte from the approved commit `edc00c4`, through `git show edc00c4:<path>`. No merge, cherry-pick or rebase was used, and no private history came along.
- The upstream integration points (`App.tsx`, `DocumentTitle.tsx`, `package.json`, `vite.config.ts`) have not changed upstream since the original's base. The original edits therefore apply unchanged, and `vite.config.ts` needs no edit.
- The runtime GLBs are the plaintext, M1-validated, lossless meshopt builds. There is no encryption, key service, envelope, manifest or placeholder mode.

**Adaptations beyond the copy** (every one is visual-neutral):

| Change | Why |
|---|---|
| `loadOpenling.ts`: `GLTFLoader().setMeshoptDecoder(MeshoptDecoder)` | The optimized GLBs use `EXT_meshopt_compression`. The decoder ships with three.js, so no new dependency |
| `OpenlingsLabPage.tsx`: the "Compare" view and its 5 reference JPEGs are removed | The JPEGs are Blender lookdev reference renders. bopi-world classifies them as private and "bopi-world only", and they are not on the authorized list. Removing the view avoids shipping a broken button |
| `officeCollision.test.ts`: decodes meshopt bufferViews before reading vertices | The test reads raw POSITION floats from the GLB |
| **Leak fix 1**, `loadOpenling.ts` `loadGltf` | Pre-existing bug. A progress listener added on a cache hit was never released, and it kept the whole `OfficeViewer` alive after unmount (about 15 MB per office remount) |
| **Leak fix 2**, `CameraRig.dispose` and `OpenlingViewer.dispose` | Pre-existing bug. OrbitControls removes its capture-phase `document` keydown listener through `domElement.getRootNode()`. React detaches the DOM before effect cleanup runs, so that is no longer the document and the listener stayed |
| **Leak fix 3**, new `releaseGpuResources(scene)` in both viewers' `dispose` | Each renderer leaves a `dispose` listener on the cached, shared GLTF geometries, materials and textures, which retained every disposed `WebGLRenderer`. This is standard three.js teardown; CPU data stays cached and the next renderer re-uploads it |
| Comments in 6 files plus the layout JSON `generator` field | Removed paths to private authoring scripts and `.blend` files that don't exist in the public repo. Wording only |
| 2 new test files | Regression tests for the lifecycle fixes. The CameraRig test was confirmed to fail without the fix |

**Chain of custody (verified by hash)**
1. The approved `feat-openlings` public GLBs are byte-identical to bopi-world `assets/openlings/runtime/*` and to the `canonicalSha256` values in `private-build/optimized/optimize-report.json`.

**Pipeline (from M1, lossless)**: strip authoring extras, dedup, prune, then `EXT_meshopt_compression` on the original float data (no quantization, filter NONE). WebP was evaluated and not applied. M1's deep fingerprint found geometry, skins, every animation channel, morph targets, materials and decoded texels bit-identical. Tolerated differences: in-triangle index rotation; 22 node TRS values within 1e-5 of identity snapped to identity (17 bone/socket scales of 0.99999994, plus 5 desk rotations of about 0.00026°); and `-0`→`+0`.

**Contents**: 1 skin with 23 joints; 6 clips (Idle, Walk, Wave, Typing, Reporting, SitIdle); 10 morph targets (4 expressions × face/eyes, plus Blink L/R; `extras.targetNames` is kept); 10 sockets; 13 `PROP_*` roots; office item, screen and sign node names. ## 8. Web / Electron compatibility

**Web: compatible.**
- Vite dev: the labs need no backend.
- `vite preview` of `dist/`: GLBs 200, no console messages.
- Backend `SpaStaticFiles` (as in `make run` and Docker), exercised with TestClient: `/lab/office` and `/lab/openlings` deep links → `index.html`; GLBs 200, `application/octet-stream`, byte-identical; missing assets → 404, not the app shell.
- Network: the office page downloads about 12.0 MB of GLBs; the lab about 6.5 MB, mostly shared and cached. The backend does not gzip static files. WebGL2 is required; without it the pages show an "unsupported" message.

**Electron: not compatible as shipped. Maintainer decision needed.** Tested in real **Electron 41.10.7 / Chromium 146**. A scratchpad harness serves `dist/` through OpenBot's own `scheme.cjs` `app://openbot` handler with the CSP from `security.cjs`, and keeps `userData` in the scratchpad.

| CSP | `/lab/office` | `/lab/openlings` |
|---|---|---|
| Current `security.cjs` | **Error**: "could not be loaded" (41 console errors) | **Error** |
| Proposed patch (below) | Ready, full Living Office UI | Ready |

Two directives block it:
1. **`script-src` has no `'wasm-unsafe-eval'`**, so `WebAssembly.instantiate` (the meshopt decoder) is refused.
2. **`connect-src` has no `blob:`**, so GLTFLoader's `ImageBitmapLoader` cannot `fetch()` the `blob:` URLs of embedded PNG textures. This one does not depend on meshopt. The approved original takes the same texture path, so I expect it fails in Electron the same way; I did not run the original in Electron to confirm.

**I did not change the CSP.** It is a security boundary: CONTRIBUTING says "Do not weaken trust boundaries without discussion", and the brief said to leave security behavior alone. Also, with no navigation entry, the desktop app cannot reach `/lab/*` today (it has no URL bar), so Electron users are not affected. If the maintainer wants the labs in the desktop app, the verified minimal patch is:

```diff
--- a/frontend/electron/security.cjs
+++ b/frontend/electron/security.cjs
@@ function contentSecurityPolicy(configuredOrigin, apiOrigin = configuredOrigin) {
     "img-src 'self' data: blob:",
     "style-src 'self' 'unsafe-inline'",
-    "script-src 'self' 'unsafe-inline'",
-    `connect-src 'self' ${configuredOrigin} ${apiOrigin}`,
+    // WebAssembly only (three.js meshopt decoder); does not allow eval() of strings
+    "script-src 'self' 'unsafe-inline' 'wasm-unsafe-eval'",
+    // GLTFLoader reads textures embedded in GLBs through same-origin blob: URLs
+    `connect-src 'self' blob: ${configuredOrigin} ${apiOrigin}`,
```

It would need a matching assertion in `electron/security.test.ts` and a navigation entry. The packaged desktop app also grows by about 16.3 MB, because `electron-builder.yml` packages `dist/**/*`.
